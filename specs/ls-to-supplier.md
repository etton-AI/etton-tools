# 朗胜(LS)转供应商模板 — 功能规格文档

> 最后更新: 2026-10-17 | 维护者: berry-bi

## 1. 功能概述

**朗胜转美线发票**（`/ls-to-supplier`）把朗胜客户的**易通下单发票**自动转换为供应商「**美线发票下单映射**」模板，消除手动「易通 → 美线发票粘贴」的重复劳动。

朗胜与其它客户的关键差异：**一个 SKU 对应一个 SO（客户订单号）**，一票源发票要按 SKU 拆分成多张美线发票。SO 号不在源发票里，需另传一份「SO-SKU 对应表」补齐。

- **输入 1**: 易通下单发票（`.xlsx`，sheet `ETTON电商物流 下单模板`）
- **输入 2**: SO-SKU 对应表（`.xlsx`，sheet `1`，A 列发票文件名 / B 列 SO / C 列 SKU）
- **界面输入**: 服务渠道（必填）、提货方式（默认「自送货」）、交货站点（默认「清溪仓」）
- **输出**: ZIP 包（每个 SO 一张 `<SO>.xlsx` 美线发票 + `转换结果汇总.json`）

## 2. 输入格式

### 2.1 易通下单发票（源，共享解析）

源结构见 `yanxun-convert.md` 的输出格式（易通下单模板）。顶部字段固定坐标：

| 字段 | 位置 |
|------|------|
| 报关方式 | B8 |
| 总箱数 | B18 |
| 带电 | F2 |
| 带磁 | F3 |
| 收件人国家 | F9 |
| 仓库代码 | F10 |

明细从 **R25** 起（A 列「货箱编号」为空结束），关键列：A 货箱编号 / B 货件追踪编码 / C 英文品名 / D 中文品名 / E 材质 / F 用途 / G 箱数 / H 总数量 / I 单价 / J 总价 / L 海关编码 / M 品牌 / N 型号 / P 净重 / Q 毛重 / R 长 / S 宽 / T 高 / Z SKU。

### 2.2 SO-SKU 对应表

- sheet 名 `1`（不存在则取第一个 sheet）
- **A 列 = 发票文件名**（合并单元格，跨行沿用当前分组）
- **B 列 = SO 号**（客户订单号，如 `LSGKJ26100033`）
- **C 列 = SKU**

## 3. 输出映射 — 美线发票下单映射

模板：`public/templates/ls-yx/美线发票下单映射-模板.xlsx`（sheet `发票`）。

### 3.1 顶部字段

| 目标 | 值来源 |
|------|--------|
| B1 客户订单号 | SO 号 |
| B2 客户参考号 | SO 号 |
| B3 服务 | 界面「服务渠道」 |
| B4 地址库编码 | 源仓库代码（触发模板 VLOOKUP 带出地址） |
| B14 带电 | 源 F2 |
| B15 带磁 | 源 F3 |
| B16 报关方式 | `报关退税 → 一般贸易`，其余 `→ 代理报关` |
| B17 箱数 | 源 G（该 SKU 行箱数） |
| E1 预计交货站点 | 界面「交货站点」 |
| E2 预计提货时间 | 今天（Excel 日期序列） |
| E3 提货方式 | 界面「提货方式」 |
| E5 涉证类型 | 固定「无」 |
| E7 出证方式 | 固定「无」 |

### 3.2 数据区（从 R19 起，18 列）

| 列 | 字段 | 值来源 |
|----|------|--------|
| A | 货箱编号 | `${boxId}U000001-${箱数}` |
| B | 英文品名 | 源 C |
| C | 中文品名 | 源 D |
| D | 单箱数量 | `总数量 / 箱数`（2 位小数） |
| E | 单价 | 源 I |
| F | 货箱重量 | 源 Q（毛重原值） |
| G/H/I | 长/宽/高 | 源 R/S/T 各 **-1**（2 位小数） |
| J | 海关编码 | 源 L（纯数字转数值） |
| K | 品牌 | 源 M |
| L | 材质 | 源 E |
| M | 型号 | 源 N |
| N | 用途 | 源 F |
| O | 产品图片 | 固定 0 |
| P | PO Number | 源 B（货件追踪编码） |
| Q | 物品箱号 | 源 G |
| R | 物品 FBA ID | 源 A |

## 4. SO 匹配逻辑（三级 fallback）

1. **按文件名分组**：`normalizeInvoiceName(源文件名)` 匹配对应表 A 列（去扩展名 / 去 `(N)` 副本标记 / 去空格）。
2. **按稳定键**：文件名中文乱码（curl/浏览器按本地代码页编码）导致整名匹配失败时，退化为 ASCII 稳定键 `日期 + 代码`（如 `2026-10-15LGB4`）。
3. **按 SKU 全局匹配**：前两级都失败时，按 SKU 在全局映射中选 SO（多个 SO 时优先选未用过的，避免重复）。

每个 SKU 可对应多个 SO（队列按顺序 `shift`），一行源明细生成一张发票。

## 5. 输出

ZIP 内每张发票以 `<SO>.xlsx` 命名，另附 `转换结果汇总.json`（源文件名 / 总数 / 跳过明细 / 警告 / 文件清单）。跳过项（无 SKU、无对应 SO）不生成发票，仅记录在汇总里。

## 6. 非目标 / 已知限制

- 一个 SKU 多 SO 时按对应表顺序分配，不做数量级拆分校验。
- 文件名中文乱码仅靠「日期 + 代码」稳定键兜底；若源文件名既无中文也无该键，且 SKU 在多张发票中重复，可能取错 SO。
