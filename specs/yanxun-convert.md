# 延讯下单优化 — 功能规格文档

> 最后更新: 2026-09-03 | 维护者: berry-bi

## 1. 功能概述

**延讯下单优化**（`/yanxun-convert`）将延讯下单发票（发货单格式）自动转换为易通下单模版格式，消除手动「延讯→易通转换模版粘贴」的重复劳动。

- **输入**: 延讯下单发票 Excel（`.xlsx` / `.xls`，发货单 sheet）；支持**批量多选**或**上传 ZIP 包**（一次处理几十票）
- **输出**: 易通下单模版（**FBA 场景用 `ETTON_FBA号` 命名，海外仓场景用 `ETTON_调拨单号` 命名**，如 `ETTON_FBA19MX7M8KR.xlsx` / `ETTON_TF2608270070.xlsx`）；支持**单票下载**或**打包 ZIP 下载**

## 2. 输入格式 — 延讯下单发票

### 2.1 顶部信息（发货单 sheet 上半部分）

| 字段 | 说明 | 位置示例 |
|------|------|---------|
| 运输方式 | 海运/空运/快递等 | R3 标签「运输方式*」→ R4 值 |
| 正式报关 | 公司自报 / 永德吉报关 / 否 | R3 标签「正式报关*」→ R4 值 |
| 带电 | 是 / 否 | R3 标签「带电*」→ R4 值 |
| 目的地 | 第 1 个=国家；第 2 个=FBA 仓库代码（FBA）或海外仓地址文本（海外仓） | R3 标签「目的地*」×3 → R4 值 |
| 渠道 | 如「易·22日达卡派」 | 「物流商/渠道」标签右侧（跳过地址类文本） |
| FBA号/海外仓 | 如 `FBA19MXX2JCW`（FBA）或「智荟海外仓：美西2号仓」（海外仓）→ 场景判断依据 | R5 标签「FBA号/海外仓」→ 右侧 |
| 调拨单号 | 如 `TF2608270070`（海外仓命名） | R5 标签「调拨单号」→ 右侧 |
| ReferenceID | 如 `183NGEAL` | R5 标签「ReferenceID」→ 右侧 |
| 总箱数 | 如 `5` / `26` | R7 标签「总箱数」→ 右侧 |

### 2.2 货箱清单（发货单 sheet 下半部分）

表头行同时含「箱号」+「发货数量」，数据行逐箱列出。关键列：

| 延讯列 | 用途 |
|--------|------|
| 箱号 | 唯一标识（混箱时重复） |
| 发货数量（包数） | → Quantity |
| 长（cm）/宽（cm）/高（cm） | → 尺寸 |
| 毛重（KG） | → 净重&毛重 |
| 品名 / 英文 | → Name(Ch) / Name(En) |
| 海关编码 | → HS Code |
| 申报货值 | → Unit Price |
| 材质（中英）/ 用途（中英） | → Material / Use |
| 币种 | → currency |

## 3. 输出格式 — 易通下单模版

内置模板 `public/templates/易通下单模版.xlsx`，主 sheet `ETTON电商物流 下单模板`。

### 3.1 顶部字段

| 易通字段 | 位置 | 来源 |
|---------|------|------|
| 业务类型 | B6 | 运输方式 |
| 报关方式 | B8 | 正式报关（映射后） |
| 带电 | F2 | 带电（否则不填） |
| 仓点类型 | F7/F8 | 仅 FBA 场景填 `FBA`；海外仓场景清空 |
| 收件人国家 | F9 | 目的地（第 1 个），仅 FBA 场景 |
| 仓库代码 | F10 | 目的地（第 2 个），仅 FBA 场景 |
| 私人地址/海外仓 | F14~F22 | 海外仓场景：收件人姓名/公司/国家/城市/州/邮编/联系方式/地址（从「目的地」地址文本解析） |
| 总箱数 | B18 | 总箱数 |
| 预计总重量 | B19 | 数据毛重合计（混箱仅首行） |
| 预计总体积 | B20 | 延讯「体积CBM」列合计（混箱仅首行） |
| 备注 | B21 | 渠道 |

### 3.2 数据区（R25 起，24 列）

Shipment ID、Reference ID、Name(En)、Name(Ch)、Material、Use、Number(箱数)、
Quantity、Unit Price、Total Price、currency、HS Code、brand、Model、Brand Type、
净重、毛重、长、宽、高、链接、图片、是否申报、申报数量。

## 4. 字段映射规则

### 4.1 报关方式映射

| 延讯「正式报关」 | 易通「报关方式」 |
|----------------|----------------|
| 公司自报 | 普通报关（买单） |
| 永德吉报关 | 报关退税 |
| 否 | 普通报关（买单） |

### 4.2 数据列映射

| 易通列 | 延讯来源 |
|--------|---------|
| Shipment ID | 箱号 |
| Reference ID | ReferenceID（顶部，FBA 场景）；`/`（海外仓场景，无追踪编码） |
| Name(En) | 英文 |
| Name(Ch) | 品名 |
| Material | 材质 |
| Use | 用途 |
| Number | 1（首行）/ 0（混箱后续行） |
| Quantity | 发货数量 |
| Unit Price | 申报货值 |
| Total Price | Quantity × Unit Price（保留完整精度） |
| currency | 币种（FBA 场景从「币种」列取）；海外仓备货单无币种列、或币种列是公式查不到值（如 VLOOKUP 返回 `#N/A`）时，默认 `USD`（美加等美元区） |
| HS Code | 海关编码 |
| brand / Model / Brand Type | 无（固定） |
| 净重 / 毛重 | 毛重（混箱后续行补 0） |
| 长 / 宽 / 高 | 长 / 宽 / 高（混箱后续行补 0） |
| 链接 | 延讯「链接」列有值则填值，无值填 `0` |
| 图片 | 无（固定填 `0`） |
| 是否申报 / 申报数量 | 留空（延讯发票无对应数据） |

## 5. 混箱处理

- **定义**: 同一「箱号」出现多行（一箱多 SKU）
- **规则**: 仅首行保留毛重/长宽高，Number 列=1；其余行 Number、净重、毛重、长、宽、高 **统一填 `0`**（不留空白）
- **目的**: 避免导入易通系统时把混箱的货当作新的一箱；补 `0` 保证下游导入不因空值报错

## 6. 必填项校验

易通模板必填项按「延讯能否自动提供」分三类处理：

**① 延讯自动填 + 缺失报错**（批量时该票进失败列表，不中断其它票）：

| 必填项 | 延讯来源 | 缺失提示 |
|--------|---------|---------|
| 业务类型 | 运输方式 | 无运输方式 |
| 报关方式 | 正式报关（映射） | 无报关方式 |
| 总箱数 | 总箱数（fallback 去重箱号数） | 自动 |
| 预计总重量 / 预计总体积 | 数据合计 | 自动 |
| 仓点类型 | FBA 场景固定 `FBA` | 自动 |
| FBA号 | FBA号/海外仓（仅 FBA 场景必填） | 无FBA号 |
| 收件人国家 | 目的地（第 1 个） | 无目的地国家 |
| 仓库代码 | 目的地（第 2 个，仅 FBA 场景） | 无仓库代码 |
| 收件人姓名 / 地址 | 海外仓地址文本（仅海外仓场景） | 无收件人姓名 / 无收件人地址 |
| 调拨单号 | 调拨单号（仅海外仓场景） | 无调拨单号 |
| 备注 | 渠道 | 无渠道名 |
| 文件名 | `ETTON_FBA号`（FBA）/ `ETTON_调拨单号`（海外仓） | 自动 |

> 渠道缺失时**不会**误填「发件人地址」；从「物流商/渠道」标签右侧多格扫描，跳过含「发件人/地址/邮编/收件/电话」的地址类文本，取第一个真正的渠道名；扫不到即视为无渠道名。

**② 模板自带默认值**（无需处理）：发货公司*（广州延讯贸易有限公司）、是否合并报关*（否）。

**③ 延讯无法自动映射 → 不做校正**：服务渠道*（延讯渠道名与易通服务渠道名非一一对应，如「FBA全美26日达快线」对应「FBA全美26日达不含税/含税」两个候选，由人工选定，转换结果不再提示）。

**二选一必填组**：`仓点类型+收件人国家+仓库代码`（FBA 地址库）与「私人地址/海外仓」组二选一。
- 「FBA号/海外仓」字段值**不含「海外仓」字眼 = FBA 场景** → 走第一组（仓点类型=`FBA`、收件人国家、仓库代码），并校验 FBA号 必填（缺失报「无FBA号」）
- 「FBA号/海外仓」字段值**含「海外仓」字眼 = 海外仓场景** → 清空第一组，走第二组「私人地址/海外仓」，从「目的地」地址文本自动解析收件人姓名/公司/地址/电话/城市/州/邮编 并填入

## 7. API 接口

### POST `/api/yanxun-convert`

- **输入**: `multipart/form-data`，字段 `files`（可多个）；支持 `.xlsx` / `.xls` / `.zip`
  - 逐个转换上传的 Excel；`.zip` 包先解压提取内部 `.xlsx/.xls`（跳过 `.` / `~$` 开头的临时文件）
- **输出**: JSON `{ sessionId, summary: {total, success, failed}, results[], failed[], downloadAllUrl }`
  - `results[]` 每项: `{ sourceFile, fileName, fbaId, totalBoxes, dataRows, mixedBoxGroups, topInfo, warnings, downloadUrl }`
  - `failed[]` 每项: `{ sourceFile, error }`（单个文件失败不中断整体）
- **限制**: `bodyParser.sizeLimit = "50mb"`

### GET `/api/yanxun-convert?session=xxx&file=yyy`

- `file=all.zip` → 打包下载所有成功结果（含 `转换结果汇总.json`，重名自动加 `_2` 后缀）
- `file=<文件名>` → 下载单个 `.xlsx` 文件
- **过期**: session 30 分钟无访问自动清除

## 8. 已知限制

- 延讯「带电」值为「否」时，易通「带电」不填（需求规则）
- 服务渠道（B7）不自动填充、不做校正（延讯渠道名与易通渠道名非一一对应，由人工选定）
- 海外仓场景（「FBA号/海外仓」字段值含「海外仓」）不填 FBA 地址库组，改为从「目的地」地址文本自动解析并填充「私人地址/海外仓」收件人信息
- brand/Model/Brand Type 固定填「无」（延讯发票不提供品牌信息）
- 链接列无数据填 `0`、图片列固定填 `0`；是否申报、申报数量列留空（延讯发票无对应数据）
- 仅处理发货单 sheet（第一个 sheet），忽略其他 sheet；实现上用 `loadFirstSheetOnly()` 在解析前先用 JSZip 精简 xlsx（只保留发货单 sheet、删除隐藏的 VLOOKUP 数据源表与外部链接），避免大文件全量解析吃内存导致 OOM——3.7MB 发票解压后达 26MB（产品资料 sheet 12MB + externalLink 6MB），精简后仅加载发货单，内存从 1GB+ 降到一两百 MB
- 模板数据区（R25 起）预置的示例行删除时用 `actualRowCount` 计算删除行数，不能用 `rowCount`（否则 `spliceRows` 静默失败，示例数据残留到输出底部）
