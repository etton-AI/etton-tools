# TR全量入仓数据整理 — 功能规格

> 状态：已实现（2026-09-08）｜路由 `/warehouse-entry-full`（逐箱版，独立于原 `/warehouse-entry`）

## 一、项目背景

原「TR入仓数据整理」（`/warehouse-entry`）按**代表箱选数**——每个 FBA 号选一个代表箱规，配合历史库对比，输出一行建议。本功能改为**逐箱输出**：一个 FBA 号下每个供应商箱各生成一行，逐箱放大尺寸、逐箱校验，无历史库依赖。适合需要「全量逐箱核对」的场景。

两功能独立并存：原功能保留代表箱选数 + 历史库；本功能为逐箱 + 11 级尺寸修正 + 无历史库。

## 二、输入数据格式

与「TR入仓数据整理」完全一致，复用同一套解析器：

- **客户数据**（三种格式自动识别）：标准 / 易通发票 / 货箱清单，见 `specs/warehouse-entry.md`「二、输入数据格式」
- **供应商数据**（逐箱，三种格式自动识别）：天图 / 英美入仓 / 给总部，见 `specs/warehouse-entry.md`「二、输入数据格式」

> 注意：两套 lib（`warehouse-entry.ts` 与 `warehouse-entry-full.ts`）各有一份格式检测常量，后续新增格式需两边同步（见 dev-spec.md #73）。

## 三、核心业务规则

### 1. 逐箱匹配
- FBA 匹配：供应商箱号取「U+流水号」前的值（`FBA19MYJ057TU000001` → `FBA19MYJ057T`），与客户 FBA ID 分组
- **逐箱输出**：一个 FBA 号下每个供应商箱各生成一行，`totalBoxes = 1`
- 未匹配到供应商箱的客户产品 → 保持一行，报警 `⚠需人工复核`

### 2. 出给客户尺寸（材积/实重主导分叉）
- **材积主导**（客户材积重 > 客户实重）→ 对该箱按 **11 级尺寸修正规则**放大
- **实重主导**（客户材积重 ≤ 客户实重）→ 取该箱原值（长宽高降序），不放大
- 材积重 = 长×宽×高 ÷ 6000；计费重 = `max(实重, 材积重)`；三边和 = 长+宽+高

### 3. 11 级尺寸修正规则（材积主导时）
先把三边降序排为 `[最长, 次长, 短]`，依次尝试规则 1–10，命中第一条「不冲突」即返回：

| 规则 | 增量 | 说明 |
|------|------|------|
| 1 | 三边各 +1 | `[+1, +1, +1]` |
| 2 | 短边 +2 | `[0, 0, +2]` |
| 3 | 次长边 + 短边各 +1 | `[0, +1, +1]` |
| 4 | 最长边 + 短边各 +1 | `[+1, 0, +1]` |
| 5 | 次长边 +2 | `[0, +2, 0]` |
| 6 | 最长边 + 次长边各 +1 | `[+1, +1, 0]` |
| 7 | 最长边 +2 | `[+2, 0, 0]` |
| 8 | 短边 +1 | `[0, 0, +1]` |
| 9 | 次长边 +1 | `[0, +1, 0]` |
| 10 | 最长边 +1 | `[+1, 0, 0]` |
| 11 | 原值兜底 | 前面全冲突时不放大 |

- **「冲突」判定**：修正后三边和 vs 客户三边和 差 ≥ 6，或 修正后材积重 vs 客户材积重 差 ≥ 2
- 输出保持 长 ≥ 宽 ≥ 高 降序；规则 11「原值」无论是否冲突都返回

### 4. 报警与容差（逐箱：该供应商箱 vs 客户申报）
| 报警 | 触发条件 | 文案 |
|------|---------|------|
| 三边和差（材积主导） | `\|出给客户三边和 − 客户三边和\| ≥ 6` | 三边和差异超限，请核查过机图 |
| 材积重差（材积主导） | `\|出给客户材积重 − 客户材积重\| ≥ 2` | 材积重差异超限，请核查过机图 |
| 实重差（实重主导） | `\|出给客户实重 − 客户实重\| ≥ 0.5` | 实重差异超限，请核查过机图 |
| 供应商过大箱 | 该 FBA 号最大材积重 − 当前箱材积重 ≥ 2 | 供应商存在过大箱，请核查过机图 |
| 建议偏小 | 出给客户计费重 < 客户计费重 | 建议数据计费重小于客户，请确认 |
| 成本重过大 | Σ出给客户总计费重 < Σ供应商该 FBA 总计费重 | 成本重过大，请和供应商申请 |
| 未匹配 | 无对应箱组 | ⚠需人工复核 |

### 5. 全局兜底校验（导出时）
- 导出前 Σ出给客户总计费重 > Σ供应商总计费重，否则等比例放大并标 `[全局调整]`（`AMPLIFY_RATIO = 1.02`）
- 放大受差异约束限制（`forceAmplify`），触达约束上限即停止；仍不足时导出弹窗提示可能亏损

## 四、无历史库（与原功能的差异）

本功能**完全去掉历史库**：
- 不读条数、不累积、无「导入/导出历史库」按钮、无历史库条数展示
- 无「建议参考历史最大值放大」报警（逐箱操作，无历史参考意义）
- API 无 GET 历史库端点、无 `/history` 子路由；导出不调用 `accumulateHistory`

## 六、导出格式

复用 `exportOutputBuffer`，与「TR入仓数据整理」完全一致的 40 列三组并排格式（见 `specs/warehouse-entry.md`「六、导出格式」）。唯一差异：逐箱模式下每行 `totalBoxes = 1`，合计总箱数 = 明细行数。
