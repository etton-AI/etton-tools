# TR入仓数据整理 — 功能规格

> 状态：已实现（2026-09-02）｜路由 `/warehouse-entry`

## 一、项目背景

用户日常需将「客户下单箱规」与「供应商实测箱规」比对，选出合理的「出给客户」箱规。此前纯人工翻历史表、比对差异，效率低且易漏报警。本模块输入客户数据 + 供应商数据，自动匹配、选数、校验、报警并导出《出给客户的.xlsx》，支持历史库累积与人工微调。

## 二、输入数据格式

### 客户数据（支持三种格式自动识别）

**格式 A — 标准客户数据**（一行一个产品）：
| 列 | 说明 |
|----|------|
| FBA ID | 12 位 |
| 中文品名 | 产品名称 |
| 总箱数 | 该产品箱数 |
| 长(CM) / 宽(CM) / 高(CM) | 客户申报箱规 |
| 实重 | 客户申报实重 |
| 材积重（可选） | 缺失时按公式计算 |

**格式 B — 易通发票**（`8月第4周（易通发票）...xlsx`，表单头 + 明细表）：
| 列 | 说明 |
|----|------|
| FBA货箱编号 | 12 位 FBA |
| 中文品名 | 产品名称 |
| 箱数/件数 | 该产品箱数 |
| 货箱重量(KG) | 客户申报箱重（=实重） |
| 长(CM) / 宽(CM) / 高(CM) | 客户申报箱规 |

**格式 C — 货箱清单**（`客户数据-给英美-0824到0830.xlsx`，表单头「货箱清单」+ 明细表）：
| 列 | 说明 |
|----|------|
| 系统SO / 客户渠道 / 国家 / 仓库代码 / 单证报关 | 客户元信息，导出列 B–F |
| FBA ID | 12 位 |
| 中文品名 | 产品名称（注意同表有「英文品名」列，勿取错） |
| 总箱数(CTN) | 该产品箱数 |
| 长(CM) / 宽(CM) / 高(CM) | 客户申报箱规 |
| 单箱货物毛重(KG) | 单箱实重（=实重） |

> 自动检测规则：表头含「FBA货箱编号」→ 按格式 B 解析；含「单箱货物毛重」→ 按格式 C 解析；否则按格式 A 解析。
> 格式 B 的「货箱重量」对应「实重」；无「材积重」列，按公式重算。
> 格式 C 的「货箱重量」是该 SO 的**总重**（如 2442.45），不可作单箱实重；实重必须精确取「单箱货物毛重」列（例：魔法球投影灯 15.15）。

### 供应商数据（逐箱，支持三种格式自动识别）

**格式 A — 天图**（`供应商的数据格式-天图.xlsx`）：
| 列 | 说明 |
|----|------|
| 货箱编号 | `FBA15M8F4YZR` + `U000001`，取「U+流水号」前的值匹配 FBA |
| 货箱长 / 货箱宽 / 货箱高 | 实测尺寸 |
| 货箱实重 / 货箱材积重 | 实测重量 |

**格式 B — 英美入仓**（`TRKJ26080105-英美入仓数据.xlsx`）：
| 列 | 说明 |
|----|------|
| 扩展箱号 | `FBA19MYJ057T` + `U000001`，取「U+流水号」前的值匹配 FBA |
| 货箱重量(BI) / 货箱长度(BJ) / 货箱宽度(BK) / 货箱高度(BL) / 货箱材积重(BM) | 实测重量与尺寸 |

**格式 C — 给总部**（`供应商数据-给总部-0824到0830 更新.xlsx`）：
| 列 | 说明 |
|----|------|
| FBA号 | `FBA19MTJH5NP` + `U000014`，取「U+流水号」前的值匹配 FBA |
| 长(CM) / 宽(CM) / 高(CM) | 实测尺寸 |
| 单件重量（KGS) / 单件材积(KGS) | 单箱实重 / 材积重（材积重已含，可直接用） |

> 自动检测规则：表头含「扩展箱号」→ 格式 B；含「单件重量」→ 格式 C；否则格式 A。
> 注意格式 B 的「货箱编号」列是运单号（`10593316U001`）而非 FBA，不可用于匹配。
> 注意格式 C 是「多个 SO 块纵向堆叠」（每块：块头 4 行 + 表头 + 逐箱数据 + TOTAL），解析时跳过块头/TOTAL/表头行（仅读 FBA 号列能提取出 `FBA+字母数字` 的数据行）；文件可能带第二个 sheet（某 SO 的重复明细），仅读第一个 sheet 避免重复计数。

## 三、核心业务规则

### 1. 产品唯一键与匹配
- 产品唯一键 = `品名 + 长 + 宽 + 高 + 实重`（品名相同但箱规不同 → 不同产品）
- FBA 匹配：供应商箱号取「U+流水号」前的值（`FBA19MYJ057TU000001` → `FBA19MYJ057T`）
- 客户文件清洗：跳过尾部汇总空行（品名/FBA 为空即停）

### 2. 选数算法
- 材积重 = 长×宽×高 ÷ 6000；计费重 = `max(实重, 材积重)`，按计费重降序
- 箱规匹配：长宽高向下取整后相等；实重容差 ≤ 0.3kg
- **选数**（按历史参考值决定取第 1 大还是第 2 大）：
  - 有历史同款：供应商第 1 大计费重 ≤ 历史最大计费重 → 取第 1 大；超过历史最大 → 退取第 2 大
  - 新品（无历史同款）：取第 2 大（避免取到偶发偏大的异常箱）
  - 仅 1 箱时回退到第 1 大
- 建议值 = 选中箱规长宽高 + 该箱规所有箱最大实重 + 公式材积重

### 3. 出给客户规则（供应商选数 + 最短边放大）
- **出给客户 = 供应商选数箱规 + 最短边 +1**：尺寸 = 选中箱长宽高，再放大最短边 +1 作安全余量（尽量不放大最大边）；实重 = 该箱规所有箱最大实重；材积重 = 公式重算；计费重 = `max(实重, 材积重)`
- **放大约束**：放大后材积重 − 客户材积重 必须 `< 2`；计费重不超过历史最大计费重（历史最大是上限）。任一不满足 → 不放大（退回供应商原尺寸）
  - 例：供应商 `54×53×36`、客户 `51.5×51.5×36` → 最多放大到 `54×53×37`（最短边 36→37），再大则材积重差 ≥ 2
- **差异约束（对比客户申报）**：三边和差必须 `< 6`、材积重差必须 `< 2`；超限 → 报警并提示找供应商核查过机图，核实后再修改
- **参考优先级**：历史有数据用历史参考；有供应商数据用供应商数据参考（供应商实测为准）。供应商数据明显偏大（如 51/51/51 vs 客户 49/49/49，三边和差 ≥ 6）→ 仍采用供应商数据，但标红要求核查过机图
- **供应商小于客户**：供应商选数箱计费重 < 客户计费重 → 出给客户取历史最大值（历史同款最大计费重对应箱规），并报警「供应商小于客户，请确认」；无历史同款则仅报警、保持供应商值
- **全局兜底**：导出前 Σ出给客户总计费重 > Σ供应商总计费重，否则等比例放大并标 `[全局调整]`（`AMPLIFY_RATIO = 1.02`）

### 4. 报警与容差
| 报警 | 触发条件 | 文案 |
|------|---------|------|
| 三边和差（材积主导） | `供应商体积重 ≥ 供应商实重` 且 `\|供应商原始三边和 − 客户三边和\| ≥ 6` | 三边和差异超限，请核查过机图 |
| 材积重差（材积主导） | `供应商体积重 ≥ 供应商实重` 且 `\|供应商原始材积重 − 客户材积重\| ≥ 2` | 材积重差异超限，请核查过机图 |
| 实重差（实重主导） | `供应商体积重 < 供应商实重` 且 `\|供应商原始实重 − 客户实重\| ≥ 0.5` | 实重差异超限，请核查过机图 |
| 供应商过大箱 | `供应商最大材积重 − 建议材积重 ≥ 2` | 供应商存在过大箱，请核查过机图 |
| 历史对比 | `历史最大计费重 > 建议计费重` | 建议参考历史最大值放大 |
| 未匹配 | 无对应箱组 | ⚠需人工复核 |

> 注：以上「供应商原始箱规」取**选数命中的供应商代表箱（未放大值）**，「客户」取客户申报值；「材积主导 / 实重主导」由供应商原始箱规的 `体积重 vs 实重` 判定。与出给客户建议值（已放大）无关。
> 注：「历史对比」按业务语义实现为「历史最大 **>** 建议值」才提示放大（与规则「选了最大还比历史小则放大」一致），原始文字「<」为笔误。

## 四、历史库机制
- 路径 `data/history.json`（运行时创建，git-ignored）
- 结构：扁平数组，每条记录一份历史产品：
  `{ productName, customerLengthCm, customerWidthCm, customerHeightCm, customerActualWeight, lengthCm, widthCm, heightCm, actualWeight, volumeWeight, chargeableWeight, updatedAt }`
  - 前半（`customer*`）= 客户申报箱规，用于**同款判定**；后半 = 出给客户建议，用于**历史最大值对比**
- **同款判定**（2026-09-02 口径）：品名一致 且 长宽高**升序排序后**逐边差 ≤ 1cm 且 实重差 ≤ 1kg。仅品名一致但箱规/重量差异更大 → 视为不同产品（不参与历史对比）
  - 长宽高排序后再比，避免同一款箱因书写顺序不同（如 `39.6×39.6×43.8` 与 `43.8×39.6×39.6`）被判成不同款
- 初始化/导入：从历史 Excel 导入，`importHistoryFromExcel` 按列自动识别两种格式：
  - **双组格式**（参考文件《拓锐入仓数据参考》等，含「客户的 / 出给客户」两组）：客户组作同款判定、出给客户组作历史最大值
  - **单组格式**（《…出给客户的.xlsx》最终数据，仅一组「长/宽/高/实重/材积重」）：该组即「最终提供给客户」的值，同款判定与历史最大值都用同一组（客户标识回填为最终值）
  - 导入时**排除「总」开头的汇总列**（总实重/总材积重/总计费重，值为单箱 × 总箱数），只取单箱值，否则会把总重量误读成单箱重量（曾出现 chargeableWeight 异常偏大）
- 更新（两种途径，语义不同）：
  - **自动累积**（每次导出后，`accumulateHistory`）：以「出给客户建议值」累积，同款取计费重**更大者**（建议值只是参考，可能因放大而偏大）
  - **手动导入最终数据**（`upsertHistoryEntry(..., { overwrite: true })`）：以我们**最终提供给客户的值**为准，同款**直接覆盖**（即便最终值更小也以最终为准）——推荐用导出的最终《出给客户的.xlsx》回填，纠正自动累积偏大的建议值
- **已知限制**：K8s 无持久卷，pod 重启后丢失 → 需用「导出历史库」备份、「导入历史库」恢复

## 六、导出格式（对齐参考文件《拓锐…入仓数据（成本）.xlsx》）

> 用户要求「按参考文件格式输出，方便人工参考调整」。导出为 40 列、表头两行、三组数据并排对比，派生列用 Excel 公式，人工改动尺寸后自动重算。

### 结构
- **第 1 行分组表头**（合并单元格）：`J1:N1`=客户的、`Q1:W1`=供应商、`Z1:AD1`=出给客户
- **第 2 行列名表头**：40 列
- **明细行**（第 3 行起，每产品一行）：按 渠道 → SO 排序；同一 SO 的 B(系统SO)/F(单证报关)/AH(总计费重)/AI(成本KG) 合并单元格
- **渠道汇总**（AK-AN 列，从第 3 行起连续填，每渠道一行；末行「合计」汇总各渠道）：AK=渠道名、AL=Σ箱数、AM=ΣAH、AN=ΣAI
- **总合计行**（末尾）：I/AG/AH/AI 的 `SUM` 汇总

### 文件名
导出文件命名为 `内部三类数据_<日期>_合计总箱数<N>.xlsx`（N = 全部明细行总箱数之和）。

### 样式（对齐参考文件《TRKJ26080099和TRKJ26080100全部数据.xlsx》）
- 字体：全表宋体 11、黑色；列名表头加粗，分组表头/数据/合计不加粗
- 分组表头三色：客户 `FFDEEBF7`（浅蓝）、供应商 `FFFBE5D6`（浅橙）、出给客户 `FFE2F0D9`（浅绿）
- 列名表头：主体 `FFADB9CA`（加粗）、分隔列 O/X `FFE2F0D9`、尾列 AK-AN `FF5B9BD5`（不加粗）、备注 AJ 无填充
- 边框：细黑边框（合计行与 AJ 列无边框）；隐藏网格线；列宽精确复刻 40 列
- 数字格式：材积重/总材积重/差异 `0.00_);[Red](0.00)`（负数红）、总实重 `0.00_`、计费重 `0_`

| 列 | 内容 | 来源 |
|----|------|------|
| A | 出货日期 | 留空（客户数据无此列） |
| B–F | 系统SO / 客户渠道 / 国家 / 仓库代码 / 单证报关 | 客户数据自动取数（B/F 按 SO 合并） |
| G / H / I | FBA ID / 中文品名 / 总箱数 | 客户数据 |
| J–N | 客户 长/宽/高/实重/材积重(公式) | 客户数据 |
| P | 差异 = 客户材积重 − 供应商材积重 | 公式 |
| Q–W | 供应商 长/宽/高/实重/材积重/总实重/总材积重 | 供应商代表箱（`SuggestionRow.supplier`，选数命中箱；未匹配留空） |
| Y | 差异 = 客户材积重 − 出给客户材积重 | 公式 |
| Z–AG | 出给客户 长/宽/高/实重/材积重/总实重/总材积重/计费重 | 建议值（`suggestion`） |
| AH | 总计费重 | 该 SO 各产品计费重(AG)之和，按 SO 合并 |
| AI | 成本KG | 留空，人工填写（按 SO 合并，可与供应商砍价后回填） |
| AJ | 备注（无表头） | 报警文案 |
| AK / AL / AM / AN | 渠道 / 箱数 / 总计费重 / 总成本重 | 渠道汇总行：AK=渠道名、AL=Σ箱数、AM=ΣAH、AN=ΣAI |

### 公式约定
- 材积重 = `长×宽×高/6000`（N、U、AD 列）
- 总实重 = `实重×总箱数`；总材积重 = `材积重×总箱数`（V/W、AE/AF 列）
- 计费重 = `ROUND(MAX(总实重, 总材积重), 0)`（AG 列）
- 总计费重 = `SUM(该 SO 的 AG 列)`（AH 列，按 SO 合并）
- 差异 = `N−U`（P 列）、`N−AD`（Y 列）
- 渠道汇总行 = `SUM` 该渠道的 I/AH/AI 列（AL/AM/AN 列）
- 总合计行 = `SUM` 明细区 I/AG/AH/AI 列

### 与旧格式的差异
旧格式为单组 13 列（FBA ID / 品名 / 总箱数 / 长宽高 / 实重 / 材积重 / 总实重 / 总材积重 / 计费重 / 总计费重 / 报警）。新格式扩展为三组并排对比，便于逐列核对「客户申报 vs 供应商实测 vs 出给客户建议」。

4. 导出后核对：三组并排、公式列可自动重算、备注列含报警、合计行正确
