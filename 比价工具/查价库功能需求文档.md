# 供应商价格库 — 美线查价功能 需求文档

> **目标读者**：Claude Code / CODEX 开发者  
> **版本**：v1.2  
> **日期**：2026-06-29  
> **MVP范围**：美线（美国FBA海运），含 ETTON / 天图通逊 / 英美跨境 三家供应商，后续扩展加拿大/英国/欧洲/澳洲/空运

---

## 1. 项目概述

### 1.1 背景

用户管理多家跨境物流供应商（易通ETTON、天图通逊、航乐、心一等），每家供应商按周发布Excel格式的报价表。当前：

- 价格数据散落在不同Excel文件中，格式各异
- 每次做账单/发票转换时需手动定位并上传价格表
- 无法快速对比「同一仓库在不同供应商、不同渠道下的价格」

### 1.2 目标

构建一个**结构化的跨供应商查价数据库**，支持：

1. **API 查询**：供 Claude Code / CODEX 等程序调用
2. **自然语言查询**：用户在 ima 中直接问「ONT8仓东莞发，美森12日达卡派，各供应商报价多少」
3. **每周更新**：导入新Excel自动覆盖旧数据

### 1.3 核心能力

```
输入：时效级别 + 船配置 + 目的仓 + 国内发货仓 + 计费方式
  ↓
输出：所有供应商在该条件下的价格、时效、赔付规则对比表
```

## 2. 统一数据模型

### 2.1 核心实体关系

```
Supplier (供应商)
  └── Channel (渠道)
        ├── speed_tier      (时效层级)
        ├── vessel_config   (船配置)
        ├── delivery_method (送仓方式: 卡派/海派/整柜直送)
        ├── destination     (目的地区域/邮编分区)
        └── PriceEntry[]    (具体价格条目)
              ├── origin_warehouse  (国内发货仓)
              ├── billing_type     (计费方式: 含税KG/不含税CBM/分区KG)
              ├── min_quantity     (起收量)
              ├── unit_price       (单价)
              ├── transit_time     (时效天数)
              ├── claim_rule       (延时赔付规则)
              ├── heavy_discount   (重货优惠阶梯)
              └── surcharges       (附加费)
```

### 3.1 通用解析流程

### 3.2 易通 ETTON 美线价格表

**识别特征**：文件名含「ETTON 易通科技物流价格表」  
**价格Sheet清单**：

| Sheet名 | 渠道类型 | 目的仓维度 | 国内仓维度 | 价格列 |
|---------|---------|-----------|-----------|--------|
| `FBA渠道` | 卡派 | 仓库代码列表 | 4个国内仓区域 | 含税KG + 不含税CBM |
| `美西整柜直送` | 整柜直送 | 仓库代码 | 4个国内仓区域 | 含税KG + 不含税CBM |
| `美西12-15日达` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG + 不含税CBM |
| `美西17-20日达` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG + 不含税CBM |
| `美西22-25日达` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG + 不含税CBM |
| `美国海派` | 海派(快递派) | 邮编分区(8-9/4-7/0-3) | 4个国内仓区域 | 12-50KG + 50KG+ |
| `美西北专线` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG |
| `美中芝加哥卡派` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG |
| `美中休斯顿卡派` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG |
| `纽约专线` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG |
| `萨凡纳专线卡派` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG |
| `东部稳速达` | 卡派(拆派) | 仓库代码 | 4个国内仓区域 | 含税KG |
| `DG海卡` | 卡派 | 仓库代码 | 4个国内仓区域 | 含税KG |

**关键解析规则**：

1. **船配置从渠道名推断**：
   - `易·12日达` → `美森正班CLX`
   - `易·15日达` → `美森正班CLX`
   - `易·17日达` → `EXX/以星带托架/合德快提统配`
   - `易·20日达` → `以星不带托架/合德普提/SEA3/CEN`
   - `易·22日达` → `COSCO/OA`
   - `易·25日达` → `OA/MSC/ONE/WHL/HMM/TSL普船统配`
   - `FBA美西28日达` → `OA/MSC/WHL统配(LA)`
   - 见附录「船配置映射表」

2. **国内仓区域映射**（4个区域，各Sheet排列顺序一致）：
   - 区域A：东莞/中山/广州
   - 区域B：嘉兴/义乌
   - 区域C：汕头/厦门/泉州
   - 区域D：武汉/长沙

3. **仓库代码行**：部分Sheet中一行包含多个仓库（如 `ONT8/LGB8/SBD1/SMF3/SCK4/...`），需拆分 `/` 为多条记录

4. **海派特殊处理**：目的维度是邮编分区而非仓库代码，`destination_type=zip_zone`

5. **重货优惠、产品附加费、计重标准**：从每个Sheet的描述文字中提取，作为该渠道下所有条目的默认值

### 3.3 天图通逊 美线价格表

**识别特征**：文件名含「天图通逊美国同行VIP价报价」  
**价格Sheet清单**：

| Sheet名 | 包含渠道 |
|---------|---------|
| `价格查询表-间接版` | 美国直送专线、美国拆派（所有渠道汇总） |
| `美国海运查询表(2)` | 直送促销价、直送快速达（含国内仓+公斤段明细） |

**关键解析规则**：

1. **渠道名称映射**（天图 vs ETTON 对应关系）：
   - `美森极速12日达` ≈ 易通 易·12日达
   - `洛杉矶CLX13日达` ≈ 易通 易·15日达
   - `洛杉矶MAX14日达` → 天图独有
   - `洛杉矶EXX16日达` ≈ 易通 易·17日达
   - `洛杉矶17日达` → 天图独有
   - `洛杉矶20日达` ≈ 易通 易·20日达
   - `洛杉矶22日达` ≈ 易通 易·22日达
   - `洛杉矶26日达` ≈ 易通 易·25日达

2. **天图渠道类型**：
   - `直送专线` → `delivery_method=整柜直送`
   - `拆派` → `delivery_method=卡派(拆派)`

3. **天图的「价格查询表」**是汇总视图，价格数据（包税/不包税）在表格内嵌。需定位到每个渠道行的具体价格列。

4. **天图另有独立的各仓库单独报价表**（如 `洛杉矶OA26日达直送-ONT8` 等），按仓库维度展开，结构不同于ETTON的「一个Sheet多仓库」。

**识别特征**：文件名含「英美跨境-美线公布价」  
**价格Sheet清单**：

| Sheet名 | 渠道类型 | 目的仓维度 | 国内仓维度 | 价格列 |
|---------|---------|-----------|-----------|--------|
| `美国海派` | 海派(快递派) | 邮编分区(美西/美中/美东) | 3个国内仓区域 | 12-100KG + 101KG起 |
| `美森海卡` | 卡派(拆派) | 仓库代码分组(逗号分隔) | 3个国内仓区域 | 12-100KG + 101KG起 + 单票价格 |
| `合德以星海卡` | 卡派(拆派) | 仓库代码分组(逗号分隔) | 3个国内仓区域 | 12-100KG + 101KG起 + 单票价格 |
| `海卡快捷查价`(Sheet1) | 卡派(拆派) | 逐仓+邮编 | 3个国内仓区域 | KG价 + 单票价格 + 按方包税 |
| `海外仓自提` | 自提 | 不区分仓库 | 3个国内仓区域 | KG价 + 单票价格 |

**渠道代码体系**（英美用字母+数字编码）：

| 代码 | 渠道全称 | 送仓方式 | 船配置 |
|------|---------|---------|--------|
| A1 | 美森正班海派 | 海派(快递派) | 美森CLX |
| A2 | 美森加班海派 | 海派(快递派) | 美森MAX |
| A4 | 华东限时达海派(18日/21日) | 海派(快递派) | 合德快提/ZIM带车架 |
| A5 | 普船统配海派 | 海派(快递派) | OA/MSC/WHL/HPL统配 |
| B1 | 美森正班海卡 / 按方包税 | 卡派(拆派) | 美森CLX |
| B4 | 华东限时达海卡 / 按方包税 | 卡派(拆派) | 合德/ZIM |
| B5 | 普船洛杉矶海卡 / 按方包税 | 卡派(拆派) | 普船统配 |
| B7 | 普船纽约海卡 / 按方包税 | 卡派(拆派) | 普船统配 |
| B8 | 美森正班/加班/合德以星/普船自提 | 海外仓自提 | 对应船司 |
| B10 | 普船奥克兰海卡 / 按方包税 | 卡派(拆派) | 普船统配 |
| B12 | 芝加哥海卡 / 按方包税 | 卡派(拆派) | COSCO/OOCL |
| B14 | 休斯顿海卡 / 按方包税 | 卡派(拆派) | WHL/HMM/海领/HPL |
| B15 | 普船洛杉矶特惠海卡 / 按方包税 | 卡派(拆派) | WHL/HMM/海领/HPL |

**国内仓区域映射**（与ETTON不同！英美有3个区域）：

- 区域A：义乌/上海/宁波/杭州
- 区域B：东莞/宝安/中山/广州/南城
- 区域C：福州/厦门/泉州/合肥/青岛/温州/汕头

**关键解析规则**：

1. **海派按邮编分区**：`destination_type=zip_zone`，分区为：
   - `美西(8,9)` → `destination_region=美西`
   - `美中(4,5,6,7)` → `destination_region=美中`
   - `美东(0,1,2,3)` → `destination_region=美东`

2. **海卡按仓库分组**：一行覆盖多个仓库（如 `FTW1，FTW5，AMA1，DFW6，SAT1，SAT4，IAH3，IUSF`），用中文逗号 `，` 分隔。需拆分为多条记录，每条对应一个仓库。

3. **海卡价格结构**：每个国内仓区域有3个子列——`12-100KG` | `101KG起` | `单票价格(元)`。其中 `12-100KG` 可能为空（`——`），表示该仓库分组不支持小重量段。

4. **按方包税**：同一渠道有「按KG」和「按方包税」两个变体（如 `B1美森正班海卡` 和 `B1美森正班海卡按方包税`），计费方式不同，需拆为两条记录。

5. **海卡快捷查价 Sheet1**：混合了所有渠道的价格行，每行标注渠道代码。部分行含附加信息（如 `B4华东限时达海卡` 和 `B4华东限时达海卡按方包税` 在同一单元格内用换行分隔）。

6. **海卡快捷查价 Sheet2-20**：纯仓库列表（仓库代码+邮编），不含价格数据——这些Sheet是对应渠道覆盖的仓库范围说明，解析时可跳过或提取仓库-邮编映射。

7. **海外仓自提**：不区分目的仓库，仅按渠道和国内仓定价。`destination_type=none`，`destination_code=*`。

8. **时效赔付**：英美有详细的赔付规则，如 `开船后第二天开始算,15天内提取-晚一天赔1元,最高赔付3元/KG`，需解析为结构化字段。

### 3.5 新增供应商解析器开发指南

当引入第四家供应商时，开发方按以下 Checklist 自助完成解析器开发。如遇歧义（尤其是渠道→船配置→时效层级的领域推断），将 Excel 提供给需求方确认映射关系。

#### Checklist

```
□ 1. 读取 Excel，列出所有 Sheet 名
□ 2. 标记哪些是价格 Sheet（含单价数据），哪些是辅助 Sheet（船期表/发货须知/仓库列表/赔偿声明）
□ 3. 对每个价格 Sheet，识别：
    □ 3a. 渠道维度 —— 渠道名列在哪？是否有渠道代码？
    □ 3b. 目的维度 —— 是仓库代码、邮编分区、还是不区分？
    □ 3c. 国内仓维度 —— 有几个区域？每个区域包含哪些城市？
    □ 3d. 价格列 —— 有几档（12KG+/50KG+/100KG+/1CBM+）？哪些是KG价哪些是CBM价？
    □ 3e. 单票价格 —— 是否有「每票最低收费」列？
    □ 3f. 时效列 —— 天数范围在哪？赔付规则在哪？
    □ 3g. 附加规则 —— 重货优惠、产品附加费、计重公式在哪？（可能在Sheet顶部文字中）
□ 4. 确定 supplier 标识字符串（与文件名匹配规则）
□ 5. 编写映射逻辑：
    □ 5a. 渠道名/代码 → channel_name, channel_code
    □ 5b. 渠道名/代码 → speed_tier（参考 §8.1 时效层级定义）
    □ 5c. 渠道名/代码 → vessel_config（常用船司关键词：美森/CLX/MAX/EXX/以星/ZIM/合德/COSCO/OA/OOCL/MSC/WHL/HPL/HMM/ONE/TSL/海领）
    □ 5d. 渠道名/代码 → delivery_method（卡派:拆派/卡派; 海派:快递派/UPS派/DPD派; 整柜直送; 海外仓自提）
    □ 5e. 国内仓城市 → origin_warehouse（归入已有区域或新建区域）
    □ 5f. 价格列 → billing_type + min_quantity + unit_price
    □ 5g. 时效文本 → transit_time_min/max + claim_threshold + claim_rate
    □ 5h. 附加规则文本 → heavy_discount (JSON) + product_surcharge (JSON)
□ 6. 编写单元测试：至少覆盖1个海派Sheet + 1个卡派Sheet
□ 7. 在 parsers/factory.py 注册新供应商 → 文件名匹配规则
□ 8. 运行导入验证：import → query → 检查数据量级和价格合理性
```

#### 格式漂移容错

供应商 Excel 是人手维护的，以下情况解析器应能容错或清晰报错：

| 异常 | 处理方式 |
|------|---------|
| Sheet 名多了空格/年份后缀 | 模糊匹配（`in` 或正则）而非精确相等 |
| 仓库代码列出现空行 | 跳过该行，记录 warning |
| 价格单元格为 `——`、`-`、空 | 识别为「该重量段不支持」，不报错 |
| 新仓库代码首次出现 | 自动插入 `warehouses` 表，标记为未确认 |
| 渠道名/代码在本供应商内不存在 | WARNING 日志 + 跳过该行，不阻断导入 |
| Excel 含合并单元格 | 用 `data_only=True` + 填充合并区域的值 |
| 文件名为 `.xls` 旧格式 | 自动切换 `xlrd` 解析 |

### 6.1 整体流程


## 7. 实现建议

### 7.1 优先级

| 优先级 | 任务 | 预计工时 |
|--------|------|---------|
| P0 | SQLite Schema + 建表 | 0.5d |
| P0 | 易通ETTON美线解析器（12个Sheet） | 2d |
| P0 | FastAPI 查询接口（§4.1-4.3） | 1d |
| P1 | 天图通逊美线解析器 | 1.5d |
| P1 | 英美跨境美线解析器（5类Sheet：海派/美森海卡/合德以星海卡/快捷查价/自提） | 1.5d |
| P1 | 导入接口（§4.4） + Excel自动识别供应商 | 1d |
| P1 | 自然语言查询意图识别 | 1d |
| P2 | 英国/欧洲/加拿大/澳洲解析器 | 按需 |
| P2 | Web管理界面 | 按需 |

### 7.2 关键技术点

1. **Excel解析**：使用 `openpyxl`（.xlsx）和 `xlrd`（.xls），`data_only=True`
2. **船配置推断**：维护一个配置映射表，从渠道名/渠道代码正则匹配
3. **仓库代码拆分**：
   - ETTON/天图：`ONT8/LGB8/SBD1` → `["ONT8","LGB8","SBD1"]`（用 `/` 分隔）
   - 英美：`FTW1，FTW5，AMA1，DFW6` → `["FTW1","FTW5","AMA1","DFW6"]`（用中文逗号 `，` 分隔）
4. **唯一键设计**：`(supplier, country, channel_name, destination_code, origin_warehouse, billing_type, min_quantity)` 唯一确定一条价格记录
5. **日期格式**：统一为 `YYYY-MM-DD`，从文件名或Sheet内提取生效日期
6. **英美特殊处理**：
   - 渠道代码（A1/B4等）作为 `channel_code` 字段
   - 「按方包税」变体与「按KG」变体分两条记录，`billing_type` 不同
   - 海卡 `12-100KG` 列可能为 `——`（空），需识别并跳过
   - 快捷查价 Sheet2-20 无价格数据，仅提取仓库-邮编映射即可

### 7.3 注意事项

- 天图的价格表结构不同于ETTON：天图是按仓库→渠道的二维表，ETTON是按渠道→仓库
- 英美的海卡按**仓库分组**（一行覆盖多个仓库），需拆分后入库
- 三家的国内仓区域划分不同：ETTON 4区、天图按渠道分、英美 3区，需各自映射
- 部分供应商价格表中含公式（`#VALUE!`/`#REF!`），需 `data_only=True` 规避
- 海派按邮编分区而非仓库，与卡派的查询维度不同
- 不同供应商对「相同渠道」命名不同（如ETTON的`易·12日达卡派` vs 天图的`美森极速12日达` vs 英美的`B1美森正班海卡`），需要在 `speed_tier` 和 `vessel_config` 层面做对齐
- 英美有「海外仓自提」类型，`destination_type=none`，不区分目的仓
